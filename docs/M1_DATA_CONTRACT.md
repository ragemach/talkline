# M1 data and local-generation contracts

Updated owner scope: slide sequences vary by concept; one or two games, exactly
two for Game Night. The v1 schema documented below is a legacy unreleased draft
with a singular `game` and fixed discussion assumptions. It does not yet satisfy
that scope. Version 2 is the next roadmap milestone, not an implemented feature.
See [research decisions](ARCHITECTURE_DECISION_FA.md).

The app still exports the five-slide prototype. `src/contracts.py` defines the
versioned **future full-kit contract**; it does not implement the 23-slide renderer
or a playable HTML game. Existing reference/template files are unchanged.

## Current application

- `src/settings.py`: immutable `EventDetails` and `UserSettings`, explicit optional
  event details and local-model preference. Defaults are empty. Dates are free text,
  not inferred. Atomic UTF-8 JSON saves live in ignored `user_data/settings.json`.
  Invalid settings are reported without overwriting the file.
- `src/ai_content.py`: one bounded retry for malformed or structurally invalid model
  responses. Local network/model errors fail immediately. Only the loopback Ollama
  endpoint is used. Explicit cloud-model names are rejected; remote models are
  filtered out of the installed-model selector.
- `review_brief`: a separate local critique of topic relevance, adult suitability,
  language levels, diversity and causal game logic. Enabled automatically in AI
  mode, with an explicit option to skip. A failed critique is shown as a warning,
  and is never described as a successful quality check. Critique is advisory,
  not a reliable CEFR certification or proof of semantic correctness.
- `regenerate_section`: updates only one validated section of a copy of the current
  brief. Failure retains the previous content. Success invalidates the old ZIP,
  renderings and critique, so the user cannot download a stale export.
- Preview and stored event metadata describe the same generation snapshot.
- The Windows launcher reuses a running Ollama server or starts the installed CLI
  in the background with cloud features disabled. It never downloads models during
  normal startup and does not block Demo when Ollama is absent or unavailable.
  Server startup logs go to `user_data/ollama-server.log` when started this way.
- Prototype exports now identify schema version, stage, engine, selected model and
  available review. The 5-slide / 2-game-card scope is explicitly retained.

## Full-kit version 1 (for M2/M3)

Owner clarification (2026-11-17): Toolkit entries now explicitly identify vocabulary,
phrases or idioms, each with a complete usage sentence. `mini_grammar` is a map by
`a2`, `b1`, `b2_c1`, each requiring an explanation, construction pattern and examples.
This revises the unreleased draft contract. Warm-ups are simple check-ins/preferences,
not tiered discussion prompts; see `docs/CONTENT_REQUIREMENTS_FA.md`.

`FULL_KIT_SCHEMA` requires `schema_version`, `topic`, `event`, `deck`, `game`, and
`invitation`. No arbitrary extra properties or model-supplied layout instructions
are accepted.

- Deck data includes three warm-ups, A2 / B1 / B2-C1 Toolkit entries with Turkish
  meanings and full English examples, mini grammar, ten tiered discussion cards,
  game rules, cooldown questions and speaker notes.
- Game data has an explicit mechanic (`patch_notes` or `smart_or_sneaky`) and exactly
  twenty Elementary and twenty Advanced cards. The shared contract represents a
  scenario, two choices, and the outcome of each choice; each engine will render
  these differently.
- IDs must be unique across all discussion and game cards. Game titles/scenarios,
  choices and outcomes are checked for normalized duplicates. Text has explicit
  character limits; Elementary card fields also have a 35-word ceiling. These are
  deterministic safeguards, not semantic level detection.
- Optional user metadata must match the `expected_event` supplied by the caller.
  The future generator must copy event metadata from the UI, never request it from
  the model. The feedback URL is optional and accepts only complete HTTP(S) URLs.
- Invitation content contains only headline and tagline. Layout/animation remains
  controlled by the rendering engine, not generated by AI.

Tests use deliberately synthetic full-kit data to test rejection of missing,
duplicated, oversized or inconsistent fields. This fixture is not a creative
40-card output and is not presented as one.

## Remaining work

Full-session generation in small batches, section editing beyond regeneration,
automatic repair policies for full sessions, reference-faithful renderers,
playable games and comprehensive visual/semantic checks remain later milestones.
Full-kit field limits may need a versioned revision after real layout QA in M2.

## Development commands

Run `.venv\Scripts\python.exe -m pytest -q` for offline tests. Run
`.venv\Scripts\python.exe scripts/smoke_ollama.py` explicitly for the real model
integration check; this is intentionally excluded from normal unit tests because
it needs an installed local model and can take several minutes.
